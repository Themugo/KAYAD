# Phase 36 — CSRF Boundary Reconciliation

## Objective
Enforce one consistent CSRF boundary across the browser-facing API while preserving authenticated JWT clients and machine-to-machine payment/webhook callbacks.

## Changes
- Added one global `csrfProtection` middleware mount under `/api` after system-status checks.
- Preserved the existing JWT Authorization exemption inside the CSRF middleware.
- Added an explicit, auditable callback exemption list for external machine callbacks:
  - `/api/payments/callback`
  - `/api/payments/b2c/callback`
  - `/api/payments/b2c/timeout`
  - `/api/bids/mpesa/callback`
  - `/api/escrow-vault/webhook/`
  - `/api/sms-bidding/webhook/`
  - `/api/webhooks/`
- Kept callback authentication in the callback routes themselves (IP whitelist, API key, webhook secret, payload validation, and/or idempotency as applicable).
- Added `scripts/validate-phase36.mjs` and `npm run validate:phase36`.

## Validation
- Global `/api` CSRF mount: PASS
- Single global CSRF mount: PASS
- JWT compatibility: PASS
- Explicit callback exemptions: PASS
- Backend middleware/server syntax: PASS

## Operational note
This phase changes browser-facing POST/PUT/PATCH/DELETE behavior: cookie-authenticated requests now require the CSRF token generated by the existing session middleware. External callbacks remain machine-authenticated and do not depend on browser sessions.
