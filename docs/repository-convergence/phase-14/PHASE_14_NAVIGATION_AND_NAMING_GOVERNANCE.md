## Naming rules for new artifacts
- New dated audit/certification evidence: `KAYAD_<SCOPE>_<ARTIFACT-TYPE>_<YYYYMMDD>.<ext>`.
- Stable maintained documentation should use concise names only where an authoritative equivalent does not already exist.
- Preserve stage IDs, timestamps, historical filenames, script paths, and manifest paths.
- Do not use `FINAL`, `CERTIFIED`, or `PRODUCTION-READY` without evidence supporting the claim.

## Structural change gate
Every move/rename/merge/delete requires exact source, destination/operation, hash, consumer analysis, explicit approval, before-state capture, rollback procedure, and post-change checks. Missing any gate means retain the current path.

## Protected document group
`KAYAD_SUPPORT_TEST_MATRIX.md` and `docs/domains/KAYAD_SUPPORT_TEST_MATRIX.md` remain separate. Their contents, provenance, and claims must not be consolidated by filename similarity alone.

## Authority labels
Use `VERIFIED_CURRENT`, `HISTORICAL_EVIDENCE`, `INFERRED`, `UNTESTED`, and `UNRESOLVED` for future handover claims. A command appearing in `package.json` is not proof it has been executed successfully.
