# Phase 3 — Topline Infrastructure & Data Foundation

## Objective

Establish a dedicated, single-business Supabase architecture for Topline Flooring & Waterproofing, completely separate from CALQULUS-PMS.

## Delivered

- Supabase Auth is the only application identity mechanism.
- Staff membership is represented by `staff_profiles` and linked directly to `auth.users`.
- Owner, administrator, manager, sales, operations, finance, marketing and staff roles are defined.
- Permissions are explicit resource/action records rather than a single boolean admin flag.
- Role assignments are stored in the database and enforced by RLS.
- Staff invitations are represented by an auditable database record.
- The admin route guard now requires an active Topline staff profile, not merely a valid Supabase session.
- The trusted owner bootstrap script creates the Auth user, staff profile and owner role assignment.
- Anonymous access to sensitive business tables is removed.
- Public catalogue/content reads remain available where required by the website.
- Admin CRUD access is permission-gated by database RLS.
- Audit records include actor user ID and actor email when available.
- Audit writes are generated by private SECURITY DEFINER triggers rather than exposed client-callable functions.
- Explicit table grants are included for the 2026 Supabase Data API exposure model.
- Historical prototype migrations are frozen and a forward migration policy is established rather than silently rewriting unknown remote history.

## Security boundary

Client-side role checks are only UX helpers. The database remains authoritative: a user without an active staff profile and appropriate permission cannot bypass RLS by calling the Data API directly.

## Dedicated project rule

Do not point this project at the CALQULUS Supabase project. Configure only the dedicated Topline project values in `.env`/deployment secrets.
