## 2. The 28 read-only routes — release-critical writes tested in isolation
A route stays "Read-only verified" when its page-level read is verified and every release-critical *write* it exposes was either (a) tested in isolation (journey 34, below) or (b) deliberately NOT executed because it moves money, calls a provider or is destructive; (b) is stated per route in the register's last column.

Journey `34_readonly_route_write_paths` (27/27, disposable DB):
* `/admin/ads` — ad-slot create/edit/delete. **Defect found and fixed:** the three write endpoints required only "any staff role", so a moderator, HR or accounts user could create, alter or delete public ad slots. Now `manage_ads` (ad_manager, marketing, admin, superadmin). Proven: 403 for moderator/hr/accounts/personal, 401 anonymous, invalid placement 400 with nothing saved, ad_manager create/edit/delete persists.
* `/admin/featured-vehicles` (campaigns) — create (validation, authorisation), end/delete need explicit confirmation, pause is repeat-safe, audit rows written.
* `/admin/staff-permissions` — only the verified System Owner may grant/revoke (an ordinary Super Admin gets 403 `SYSTEM_OWNER_REQUIRED` — existing design, unchanged); ordinary Admin 403; unknown key 400; a granted `view_system_health` opens system health for that user after re-login.
* `/admin/auctions`, `/admin/bids` — **Defect found and fixed:** `POST /api/bids/:id/end` required only any staff role; now `manage_auctions`. Authorisation and unknown-auction paths tested; **no auction was ended.**
* `/admin/transactions`, `/admin/escrows`, payout-account review — authorisation/validation only (doc 24). **Defect fixed:** dealer payout-account review required only any staff role; now `manage_payments`.
