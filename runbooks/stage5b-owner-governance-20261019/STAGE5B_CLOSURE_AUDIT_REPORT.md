# Stage 5B closure — independent owner-governance audit

Method: the implementation was read end to end (registry, governance service, routes, config predicate, auth middleware, login/refresh/optional-auth, socket auth, server wiring, bootstrap CLI, email/communication path, UI, candidate SQL) and every grant/accept/revoke/remove/recover path was traced, including older routes, seed, refresh, aliases and direct service calls. Findings that failed a test were fixed (see DEFECT_LEDGER_5B_CLOSURE.md). "Evidence" names tests that were **executed in this closure run** (tiers: M mocked, R real local stack, P disposable PostgreSQL). Nothing reached hosted (H) or live (L).

## Bypass search results
Searched for every writer of `role`, `emailVerified`, `webhoist`, `superadmin`, `isOwner*` and every `owner_memberships` writer. Only SECURITY DEFINER functions write memberships; the only application writers of verified-state for arbitrary addresses (staff creation, inspector approval) are now guarded. Direct service calls cannot create membership without the lock-protected functions (table privileges revoked from all API roles, SELECT only for service_role).

## Residual risks (not defects)
Per-instance step-up lockout; ex-owner users cannot be hard-deleted (by design); legacy/emergency modes are operator-controlled break-glass states; live e-mail deliverability unproven; hosted schema unverified. See UNRESOLVED_BLOCKERS_5B.md.
